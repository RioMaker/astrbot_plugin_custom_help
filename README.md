# 自定义群聊帮助 v2.3.2

在 AstrBot WebUI 中创建帮助模板、编辑插件说明与顺序，再勾选应用的群聊。一份模板可供多个群共用，快捷帮助可按群开启。群内 `/help`、`/帮助` 使用当前群配置生成图片，仍以优先级 1000 停止后续默认帮助响应。

## 使用

1. 更新插件并安装 `requirements.txt`（Pillow），在 AstrBot 中重载。
2. 打开插件详情 → **群聊帮助工作台**。
3. 先编辑“默认模板”：设置标题、开场说明、插件帮助清单、页尾；勾选要展示的插件，用上下箭头排序，展开“编辑说明”修改每项名称与正文。
4. 点击左侧“新建模板”，或复制现有模板，填写模板名称。在“应用群聊”中勾选一个或多个群，也可搜索后批量应用。左侧将默认模板与各独立模板分开，展开可查看所属群。
5. 按需勾选模板的三个快捷入口：@ 机器人、点名、戳一戳；点名默认“可可子”，可修改。点击“为本模板的群开启快捷帮助”，或逐群勾选右侧“群快捷帮助总开关”。状态提示显示实际启用群数；模板已勾选但群开关关闭时会明确提醒。群行中的“仅 /help”表示快捷帮助尚未开启。
6. 选择具体群生成预览，检查后点击“保存全部修改”。群内 `/help` 和已启用的快捷入口会返回同一份帮助图，保存后无需重载。

清单的 `{plugins}` 会被已勾选插件名称按拼接顺序替换。清单标题和说明都可编辑，插件名称也可编辑；删除占位符时会在说明后附加实际清单，避免表头漏列插件。纯文本换行会保留，不执行 HTML。

**帮助展示开关只决定帮助图包含哪些说明，不会启停其他插件，也不会改变其他插件的授权。** 全部取消勾选时，帮助图明确显示暂无插件帮助。图片过长时自动按阅读顺序分页，页面预览展示全部图片，群里依次发送相同图片。

## 帮助模板与群绑定

- 一个群只使用一个模板。勾选已属于其他模板的群会移动到当前模板；取消勾选或删除模板后回到默认模板。删除模板前页面会展示受影响的群数。
- 模板可创建、复制、改名、删除；每份模板独立保存文案、插件选择、顺序和三个快捷入口。修改后影响所有绑定群，快捷帮助总开关按群保留。
- 默认模板不能删除，服务于新发现和未绑定独立模板的群。新发现的群快捷帮助默认关闭；`/help`、`/帮助` 仍可使用。
- 选择“预览群聊”可带上该群名称生成实际图片；模板预览不添加群名。所有更改保存后才对群内生效。

## @、点名和戳一戳帮助

三个入口可同时开启，**需要模板中的入口已勾选，且该群的“快捷帮助”已开启**。

- **@ 机器人**：只 @ 当前机器人，可附带空白或不可见字符。带普通聊天文字、图片、引用或其他 @ 对象时不作为快捷帮助。
- **点名**：独立发送模板设置的完整名称，例如“可可子”或自定义的“小可”。句子中包含名称不触发；名称不是 AI 理解条件。
- **戳一戳**：收到 QQ OneBot / aiocqhttp 等适配器提供的真实群通知，且目标是当前机器人时触发。不把文字或 CQ 字符串当成戳一戳通知。
- 私聊、机器人自身消息和已被识别的指令不触发快捷帮助。返回内容与该群 `/help` 一致，图片失败时回退为同内容文字；不调用模型。

### 六爻与门禁配套更新

六爻 **v0.33.3** 移除了旧 `mention_help_group_ids` 和通用 @ 兜底，保留 `/六爻`、`/起卦 六爻` 自身帮助和揭晓收集。请在本页面重新选择启用快捷帮助的群；不会自动复制旧六爻群号，也不再把普通 @ 聊天作为六爻帮助请求。

若同时使用门禁插件，需配套更新至 **v2.4.3**。门禁先执行白名单与休息时段检查，再将允许的快捷入口交给本插件。命中帮助时只发送帮助图，戳一戳积分仍按原设置入账，但不叠加奖励图或文字、不重复发奖；帮助发送失败也不会影响已满足条件的奖励记账。全局禁用或被 AstrBot 会话插件配置过滤的自定义帮助不会被调用。未启用快捷帮助时保留原有门禁唤醒和戳一戳回复。

更新文件后须在 AstrBot 重载自定义帮助与门禁插件，必要时重启 AstrBot。若 `/help` 正常、快捷入口仍返回“我在，请继续说”，核对目标群的快捷帮助开关及平台实例 ID，并查看日志中的“自定义帮助快捷入口处理失败”或运行实例重载提示；登记版本号本身不能证明运行实例已更新。

## 帮助图片风格

v2.2.1 仅将「AI 生图与动图」帮助栏目改为**可可子风格**：奶油白底、浅绿圆角卡片、彩虹点缀和可可子角色插画，该栏目的续页沿用相同风格。表头清单与页尾采用原来的科技风，六爻、紫微、RTLink 等栏目继续使用各自原生样式，其他栏目保留原来的科技风。

生图栏目的插画与字体随帮助插件打包，不依赖投喂插件，不调用生成服务，来源见 [资源说明](assets/README.md)。管理页预览与群内回复共用渲染器；各群已编辑的标题、说明、顺序和展示开关继续生效。此前的全局主题选项已移除，旧设置不会将其他栏目改成可可子风格。

### 科技风清单与原生插件样式

开头的插件帮助清单使用 custom_help 自身的深蓝网格、青色线条与编号卡片科技风。各插件说明独立绘制后按群内顺序拼接，保留各自背景、字体和装饰，不再被统一改成一种底色。超长内容按完整图卡分页；单个插件超长时生成带标题的续图，不从图片中间硬切文字。

目前确认有专用图片帮助的三个插件已适配：

| 插件 | 实际读取来源 | 保留的风格 |
| --- | --- | --- |
| 六爻 | 安装目录的 `renderer.py`、`textcard.py`、`assets/bamboo.png` 和原配字体 | 米白竹影、太极、双线边框、青玉强调块与标题字体 |
| 紫微斗数 | `themes.py`、`starfield.py`、`help_renderer.py`，以及运行中插件的主题和字体设置 | 深蓝星空／浅色星轨、淡金配色、星轨标记、原生星座装饰 |
| RTLink | `help_image.py` 与 `resource/NotoSansCJKsc-Regular.otf` | 白底、紫色强调、文档式图卡和原配字体 |

样式按当前安装文件读取，优先定位 AstrBot 已加载实例，兼容 `rt_link` 等安装目录名及 `metadata.yaml` 记录的自定义目录。无对应原生图片帮助的插件用科技风承接。原插件缺失、资源不完整或源码结构暂不兼容时，仅该插件回退科技风，配置页会显示原因。升级原插件后重新生成预览即可重新检测，样式源码、字体资源或主题变化会使图片缓存失效。

原帮助图常常写死指令布局，不能直接容纳任意编辑内容。本插件读取原生配色、字体和装饰，用可变高度布局排版后台保存的标题与正文；**不会用原插件的固定帮助文字覆盖编辑内容**，也不会改变原插件的帮助指令。读取仅限已适配的样式常量与白名单绘图函数，不导入插件入口、不启动排盘、数据库、模型或网络调用。

配置页每项显示风格标签及来源文件，预览支持点击放大。后端预览和群内 `/help` 使用同一批样式与拼接逻辑。此处读取的是部署机器上对应插件的安装文件，因此服务器上也需要安装相应插件才能显示其原生风格。

## 群聊自动发现

- 启动后、每五分钟以及点击“刷新群聊”时，通过已连接的 QQ OneBot / aiocqhttp 平台获取群列表。
- 支持同一适配器的多个反向 WebSocket 机器人；以 **平台实例 ID + 群 ID** 隔离配置。
- 所有平台在收到群消息时补充登记；不提供群列表的平台需要先收到消息。
- 查询失败保留已有群和配置，在页面提示；不会因为机器人临时离线删除配置。新群继承默认模板。

## 初始说明库

覆盖本地 20 个目录、19 个独立插件。重复欢迎插件目录合并为一个帮助项；默认展示附件中已启用的 14 个自有插件。完整文字与源码出处见 [插件说明清单](docs/PLUGIN_CATALOG.md)，原始种子在 `help_catalog.json`。

这是随插件发布的默认文字说明库，无需运行服务器存在开发工作区。原生风格另外读取同一 AstrBot 下已安装插件的样式文件。说明库整体依据 2026-11-06 本地源码，生图部分于 2026-11-10 同步至 v0.3.8，补充 `/随机拼图`、`/拼图`、直接附图参考与画廊区别；部署版本差异已列在清单中。后续源码改动需随种子更新，已有模板中新增项默认关闭。

## 保存、升级与兼容

- 持久数据位于 AstrBot 插件数据目录 `astrbot_plugin_custom_help/help_profiles.json`，与插件源码分离。采用原子替换写入，保存失败保留原配置；文件损坏时明确报错，不静默覆盖。
- v2.3.0 首次加载旧版按群配置时，先保存 `help_profiles.v1.backup.json`，再将每个独立群配置迁为一个模板并绑定原群；默认模板、文字、顺序、开关均保留。快捷帮助总开关默认关闭。迁移使用原子保存并提升修订号，重复重载不会重新创建模板；旧页面草稿须导出后重新载入，不能覆盖新结构。
- v2.2.0 重载时同步默认模板及各群中未经改写的旧版生图正文：仅匹配说明库明确列出的完整旧原文，标题、开关、顺序及手动编辑的正文均保留。迁移原子保存并更新配置版本；若启用说明总字数会超限，则保留旧正文。已自定义生图正文的群可在帮助工作台自行补充新指令。
- 首次从 v1 升级时，原 `help_text` 作为默认图片引言保留；超过 3000 字则引言改为明确的迁移提示，完整原文仍保留在旧配置中。私聊仍返回该文字；留空或仍是旧默认提示时，私聊返回默认模板文字版。
- 多页面同时修改有版本冲突保护。冲突时页面保留草稿，可导出后重新载入；预览不会保存配置。只有保存成功才生效。
- 后端 API 使用 AstrBot Dashboard 身份校验，前端使用官方 Plugin View / Page bridge；未登录请求被拒绝。插件重载会清理旧路由和后台任务。
- 支持提供 Plugin Pages 与 `astrbot.api.web` 的 AstrBot（元数据最低版本 4.24.0）；若安装版本缺少页面 API，需升级 AstrBot。页面实现沿用兼容目录 `pages/manage/`。
- 图片由 Pillow 离线生成，预览和聊天共用相同渲染器，并有限量内存缓存；无需模型、网络截图服务或浏览器。图片生成失败时退回同内容文字，避免吞掉帮助请求。回复使用普通协程逐页直接发送，停止默认帮助的事件标记不会中断后续图片。

## 依赖与字体

v2.3.1 为中文字体缺失的 `🍫` 内置彩色图标，统一处理标题、群名、清单、正文和页尾的测量、换行与绘制。保留原始文字和空格，预览与群内图片共用此修复；无额外运行依赖或在线请求。图标来源与许可见 [资源说明](assets/README.md)。

`requirements.txt` 声明 Pillow。内附 Noto Sans SC 字体，使用 SIL Open Font License，许可在 [assets/fonts/OFL.txt](assets/fonts/OFL.txt)。字体资源沿用本工作区生图插件的字体资产，避免 Linux 部署缺少中文字库。

## 验证

本地运行 `python -m pytest -q`，涵盖共享模板与群迁移、备份及写入失败保护、按平台隔离、三种快捷入口与排除条件、只发送一次、重启持久化、并发修改冲突、输入验证、登录校验、群发现、指令拦截及图片分页。浏览器验证脚本见 `scripts/browser_smoke.py`，使用模拟 Bridge 连接真实配置服务与渲染器，不连接真实机器人。

`tests/test_access_gate_integration.py` 在相邻门禁仓库可用时调用两个插件的真实处理函数、帮助渲染器和 SQLite 积分账本，验证快捷帮助图片与 `/help` 一致、戳一戳三种回复模式均不叠加奖励回复、发送失败不影响积分记账，并覆盖群开关、模板开关、会话禁用和门禁白名单。AstrBot 传输层仍为本地替身，这些结果不等于真实 QQ 线上验证。

v2.2.1 验证可可子风格仅用于生图栏目及其续页，表头、页尾与其他栏目维持原样，旧全局主题设置不再影响输出。另验证插画缺失兼容、旧默认正文更新、独立群与继承群、编辑内容保留、重复重载、字数上限及写入失败保护。

v2.1.0 另验证原生样式文件读取、改名安装目录、源文件变化后的缓存刷新、资源缺失回退、按实际主题切换、编辑内容保留和完整图卡拼接。`tests/test_styles.py` 的真实相邻插件集成用例在缺少这些插件的独立环境中跳过；其他测试自建隔离样式样本。
